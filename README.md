# Stanislav Vakhnov — portfolio

Статический сайт: HTML, CSS и локальные JavaScript-библиотеки. Установка пакетов и сборка для просмотра не нужны.

## Локальный просмотр

В папке проекта запустите:

```powershell
node preview.mjs
```

Откройте http://127.0.0.1:8000/. Остановка сервера: Ctrl+C. Сервер слушает только локальный адрес, не публикует сайт, не выполняет Git-команды и не показывает служебные файлы проекта.

Дополнительные окна проверки: http://127.0.0.1:8000/__preview/mobile (390 px) и http://127.0.0.1:8000/__preview/desktop (1440 px). Это вспомогательные страницы локального сервера, они не входят в интерфейс портфолио.

Vimeo и Google Fonts требуют подключения к интернету. Изменения файлов видны после обновления страницы.

## Где редактировать

- `index.html` — контент и структура страницы.
- `assets/css/main.css` — очищенные базовые стили: типографика, компоненты и адаптивные правила. Это редактируемый CSS, компиляция SCSS не нужна.
- `assets/css/portfolio.css` — оформление портфолио и его адаптивность. Подключён после базовых стилей.
- `assets/js/portfolio.js` — меню, курсор, анимация текста, счётчики, отзывы и загрузка дополнительных работ при раскрытии.
- `assets/css/all.min.css` — небольшой набор реально используемых иконок Font Awesome; нужны два файла WOFF2 в `assets/webfonts/`.
- `assets/css/animate.css` — только используемые анимации появления.

Из внешних JS-библиотек используются Swiper, WOW и Typed.js; их файлы хранятся локально. Счётчики используют встроенные возможности браузера. Bootstrap нужен только как CSS-сетка и набор утилит. jQuery, старый скрипт шаблона, неиспользуемые плагины, SCSS, source map и лишние ассеты удалены. Скриптов публикации нет.

## Видео и бегущая строка

У iframe сохранены проверенные размеры oEmbed для резервирования места. Перед приближением видео к видимой области `portfolio.js` обновляет пропорции через публичный Vimeo oEmbed; при ошибке сети остаются сохранённые значения. Новым роликам также задавайте `width` и `height`, соответствующие их формату. Ширина карточек в строке определяется пропорциями видео, на мобильном каждая карточка занимает отдельную строку.

Бегущая строка состоит из двух одинаковых блоков без сжатия; каждый не уже окна браузера. Не изменяйте текст только в одной копии: для бесшовного цикла они должны совпадать.

## Дополнительные работы

Блок `more_work_id` расположен сразу после брендовых кейсов. Пять категорий используют встроенные HTML-элементы `details` и `summary`: их можно независимо раскрывать мышью или клавишами Enter/Пробел. По умолчанию все категории закрыты.

Видео каждой категории находятся внутри `template.work-videos-template`. Для замены ролика измените его `iframe src`, название и резервные размеры `width`/`height`, а также пропорции у родительской колонки. Порядок категорий задаётся порядком `details` в HTML; количество видео в подписи редактируется рядом с названием.

До первого раскрытия плееры не создаются, запросов к Vimeo для этой категории нет. При раскрытии загружаются только её ролики и уточняются их размеры. При сворачивании плееры получают команду паузы; при повторном раскрытии используются те же экземпляры, без пересоздания. Обложки остаются из Vimeo. Без JavaScript доступны прямые ссылки на видео.

## Заготовка кейса и процесс работы

В `index.html` найдите `case-study-example`: это скрытый HTML-шаблон с русскими комментариями. Скопируйте только `article` из него в контейнер Portfolio, возле нужного клиента перед существующим `project-wrapper`. Замените текст в квадратных скобках. Сам `template` на странице не отображается, а скопированный `article` уже имеет оформление. Пример не добавляет плеер и не меняет существующие видео.

Секция `process_id` между услугами и опытом содержит четыре этапа работы. Названия и описания редактируются прямо в списке `process-list` в `index.html`. Векторные иконки встроены в HTML как SVG; соединяющая линия становится вертикальной на мобильном экране. Для изменения графики не нужны изображения или дополнительные библиотеки.
